## Context

This skill MUST be used before any creative work. It guides collaborative design refinement through Socratic dialogue — exploring user intent, requirements, and design before implementation begins.

## Patterns

1. **Understand context first** — Review current project state before asking questions
2. **Ask questions one at a time** — Refine the idea through natural dialogue, not a questionnaire
3. **Present design in chunks** — Short enough sections to actually read and digest
4. **Get explicit approval** — Do NOT proceed to implementation until the user approves the design
5. **Save the design document** — Persist the approved design for reference during implementation

### Hard Gate

Do NOT invoke any implementation skill, write any code, scaffold any project, or take any implementation action until a design has been presented and the user has approved it. This applies to EVERY project regardless of perceived simplicity.

## Examples

**Trigger:** "Let's build a recipe sharing app"
→ Start brainstorming: ask about users, features, constraints, tech stack — one question at a time.

**Trigger:** "Add a login page"
→ Brainstorm first: What auth method? OAuth? Email/password? What's the UX?

## Anti-Patterns

- Jumping straight to code without understanding the full picture
- Asking 10 questions at once (overwhelms the human)
- Treating brainstorming as optional for "simple" tasks
- Skipping design approval before implementation
